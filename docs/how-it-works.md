# 它是怎么工作的

## 1. 为什么不是“让几个模型聊聊天”

多模型聊天很容易变成：

- 后说的附和先说的；
- 贵模型的话被默认正确；
- 大家都在复述题目；
- 没有人负责验证。

议会用四个机制避免：

| 机制 | 解决什么 |
|---|---|
| 独立提案 | 从众/锚定 |
| 匿名互评 | 品牌/价格偏见 |
| 反方席位 | 只找支持证据 |
| 独立验收 | 执行者自判 |

## 2. 阶段拆解

### 阶段 0 · 备料

产出**上下文包**（≤1200 字）：

```text
真实目标：
成功标准：
现状事实（含报错原文）：
硬约束：
验证手段：
```

规则：

- 事实与推断分开。
- 报错贴原文，不转述。
- 不知道就写“未知”，不要补。
- 用户给过的 `P0` 原文保留，不改写。

### 阶段 1 · 独立提案

每个席位拿到**同一份上下文包**，但角色/检查清单不同。

固定输出：

```text
核心思路：
具体步骤：
关键决策：
风险：
KILL CRITERIA：
最有把握：
最没把握：
```

为什么限制 400 字：

- 强迫取舍；
- 降低 token；
- 让互评能读完。

完整版可以落盘，不占对话。

### 阶段 2 · 匿名互评

把候选编号 `A/B/C/...`，不告诉评审员谁写的。

评审员输出：

```text
【硬伤】逐份，一句话
【新增洞察】所有提案都漏掉的一点
FINAL RANKING:
1. Response X
2. ...
```

为什么要匿名：

- 避免“这是强模型写的，应该对”；
- 避免“这是我自己的方案，不能输”；
- 让评审只看内容。

### 阶段 3 · 加权 Borda

假设 5 个候选，评审排名第 1 得 5 分，第 5 得 1 分。
每个评审有 weight，乘上去累加。

```text
score(candidate) = Σ weight(reviewer) × borda(reviewer, candidate)
```

均值只作参考，因为：

- 模型给自己打 9 分很常见；
- Borda 更抗“分数通胀”。

裁决：

- 共识直接采纳；
- 分歧看证据；
- 2 席以上指出的硬伤必须修；
- 分差 <15% 选可逆方案，写切换条件。

### 阶段 4 · 执行 + 验收

执行者每步写证据：

```text
命令：
原始输出：
改动：
验收判据：
```

独立验收员：

- 自己重跑；
- 核对声称；
- 查越界；
- 给 `PASS/FAIL`。

为什么执行者不能自判：

- “我改了”不等于“改对了”；
- “测试通过”不等于“测试覆盖了”；
- “看起来没问题”不是证据。

### 阶段 5 · 降级

```text
单席失败
├─ 重试 1 次
├─ 换备用模型 1 次
└─ 仍失败 → 标记掉线，继续

有效席位 < 3
└─ 停止议会，报告谁挂了
```

为什么不硬凑：

- 2 个模型容易同源；
- 少席位的“共识”不可信；
- 停比编好。

## 3. P0 规则

用户说“刚才那个方案”时：

1. 原文抓出来，记 `P0`。
2. 新提案仍要出。
3. `P0` 匿名混入候选。
4. 如果 `P0` 不低于最高分 -15%，优先保留。
5. 只合并其他提案的改进点。

目的：**不轻易推翻用户已经认可的东西**，但也不让它免检。

## 4. 成本从哪来

| 阶段 | 调用次数 | 说明 |
|---|---|---|
| 提案 | 5 | 每席一次 |
| 互评 | 5 | 每席一次 |
| 抽样 | 2–5 | 架构/反方/交付 |
| 执行 | 1+ | 按步骤 |
| 验收 | 1+ | 每步/关键步 |

所以：

- `quick` 只提案，最便宜；
- 默认 5 席 + 互评，中等；
- `wide` 6 席，更贵；
- 上下文越长越贵。

## 5. 什么时候会失败

| 失败 | 原因 | 处理 |
|---|---|---|
| 答案同质 | 都继承同一模型 | 配不同模型 |
| 互评走形式 | 模型不够强/上下文太长 | 换模型、裁剪材料 |
| 假共识 | 评审没认真读 | 强调硬伤/匿名 |
| 编造 | 上下文不足 | 要求标未知、查事实 |
| 执行跑偏 | 定稿不具体 | 步骤写清文件/命令/验收 |
| 验收放水 | verifier 太弱 | 换严格模型、要求原始输出 |

## 6. 设计取舍

| 选择 | 好处 | 代价 |
|---|---|---|
| 5 席 | 视角够多 | 贵、慢 |
| 匿名 | 减少偏见 | 实现麻烦 |
| Borda | 抗分数通胀 | 需要排名质量 |
| 独立验收 | 防自欺 | 多一次调用 |
| 静默 | 聊天干净 | 过程不透明 |
| 落盘 | 可追溯 | 要管文件 |

## 7. 一句话总结

议会不是“让 AI 更聪明”，是**让错误更早暴露**。
它用多角色、匿名、反方、验收，把“看起来对”压到“有证据”。
